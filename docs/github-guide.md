# Οδηγίες GitHub — ενημέρωση και δημοσίευση νέων εκδόσεων

Οι οδηγίες αυτές απευθύνονται σε κάποιον που **δεν έχει ξαναχρησιμοποιήσει** το GitHub. Εξηγούν
πώς ανεβαίνει μια νέα έκδοση της εφαρμογής, πώς χτίζεται αυτόματα το πρόγραμμα εγκατάστασης και
πώς φτάνει η ενημέρωση στον υπολογιστή που χρησιμοποιεί την εφαρμογή.

---

## 1. Τι είναι τι (λεξιλόγιο σε απλά ελληνικά)

| Όρος | Τι σημαίνει εδώ |
| --- | --- |
| **Repository (repo)** | Ο «φάκελος» του έργου στο GitHub: `github.com/EDaskal/MATHEMATICS`. Περιέχει τον κώδικα της εφαρμογής. |
| **Commit** | Μια «αποθήκευση με περιγραφή»: ένα στιγμιότυπο των αρχείων με ένα σύντομο σχόλιο (π.χ. «Έκδοση 1.7.0»). |
| **Push** | Ανέβασμα των commits από τον υπολογιστή σας στο GitHub. |
| **GitHub Desktop** | Δωρεάν πρόγραμμα με κουμπιά για commit και push, χωρίς εντολές. |
| **Actions** | Το «εργοστάσιο» του GitHub: σε κάθε push χτίζει αυτόματα σε Windows το πρόγραμμα εγκατάστασης. |
| **Build / Run** | Μία εκτέλεση του εργοστασίου. Κίτρινο = σε εξέλιξη, πράσινο ✓ = επιτυχία, κόκκινο ✕ = αποτυχία. |
| **Artifact** | Το αρχείο που βγάζει ένα build (το πρόγραμμα εγκατάστασης), διαθέσιμο για 30 ημέρες. |
| **Release (έκδοση)** | Μόνιμη δημοσίευση μιας έκδοσης, π.χ. «Έκδοση 1.1.0», με το πρόγραμμα εγκατάστασης και το «Τι νέο». **Από εδώ ελέγχει η εφαρμογή για ενημερώσεις.** |
| **Tag** | Η «ετικέτα» μιας έκδοσης, π.χ. `v1.1.0`. Τη δημιουργεί αυτόματα το build. |
| **Αριθμός έκδοσης** | `ΜΕΙΖΩΝ.ΕΛΑΣΣΩΝ.ΔΙΟΡΘΩΣΗ`, π.χ. 1.1.0. Βρίσκεται στο αρχείο `app/__init__.py` και τον αλλάζει ο Claude σε κάθε νέα έκδοση. |

### Πώς «ρέει» μια νέα έκδοση

```
Ο Claude σας δίνει zip με τη νέα έκδοση
        ↓  (αντιγράφετε τα αρχεία στον φάκελο του repository)
GitHub Desktop: Commit → Push
        ↓  (αυτόματα, περίπου 6–10 λεπτά)
GitHub Actions: δοκιμές → χτίσιμο .exe → αυτοέλεγχος → πρόγραμμα εγκατάστασης
        ↓  (αυτόματα, αν ο αριθμός έκδοσης είναι νέος)
GitHub Release «Έκδοση X.Y.Z» με το Diagonismata-Setup-X.Y.Z.exe
        ↓  (την επόμενη φορά που ανοίγει η εφαρμογή)
«Υπάρχει νέα έκδοση» → Λήψη και εγκατάσταση → η εφαρμογή ξανανοίγει ενημερωμένη
```

**Δεν χρειάζεται να δημιουργήσετε εσείς Release ή tag.** Το build το κάνει μόνο του όταν βλέπει
νέο αριθμό έκδοσης.

## 2. Εγκατάσταση του GitHub Desktop (μία φορά σε κάθε υπολογιστή)

Χρειάζεται μόνο στον υπολογιστή από τον οποίο **ανεβάζετε** τις νέες εκδόσεις, όχι στον υπολογιστή
όπου απλώς χρησιμοποιείται η εφαρμογή.

### Windows
1. Ανοίξτε το **https://desktop.github.com** και πατήστε **Download for Windows**.
2. Τρέξτε το αρχείο που κατέβηκε (`GitHubDesktopSetup-x64.exe`). Εγκαθίσταται και ανοίγει μόνο του.
3. Πατήστε **Sign in to GitHub.com**. Ανοίγει ο browser: συνδεθείτε με τον λογαριασμό **EDaskal**
   και πατήστε **Authorize desktop**. Αν ο browser ρωτήσει αν θα ανοίξει το GitHub Desktop, πατήστε **Άνοιγμα**.
4. Στην οθόνη «Configure Git» αφήστε όνομα και email όπως είναι και πατήστε **Finish**.

### Mac
1. Ανοίξτε το **https://desktop.github.com** και πατήστε **Download for macOS** (διαλέγει μόνο του
   Apple Silicon ή Intel).
2. Στις **Λήψεις** κάντε διπλό κλικ στο zip που κατέβηκε. Εμφανίζεται η εφαρμογή **GitHub Desktop**.
3. Σύρετε την εφαρμογή στον φάκελο **Εφαρμογές** (Applications) και ανοίξτε την από εκεί. Αν το Mac
   ρωτήσει «Είστε βέβαιοι ότι θέλετε να το ανοίξετε;», πατήστε **Άνοιγμα**.
4. Πατήστε **Sign in to GitHub.com** → συνδεθείτε στον browser ως **EDaskal** → **Authorize desktop**
   → **Άνοιγμα GitHub Desktop**.
5. Στο «Configure Git» πατήστε **Finish**.

## 3. Αντίγραφο του repository στον υπολογιστή (μία φορά σε κάθε υπολογιστή)

1. Στο GitHub Desktop: **File → Clone repository…**
2. Καρτέλα **GitHub.com**, επιλέξτε **EDaskal/MATHEMATICS**.
3. Στο **Local path** αφήστε την προεπιλογή και σημειώστε πού είναι:
   - **Windows:** `C:\Users\<όνομα>\Documents\GitHub\MATHEMATICS`
   - **Mac:** `/Users/<όνομα>/Documents/GitHub/MATHEMATICS` (στο Finder: Έγγραφα → GitHub → MATHEMATICS)
4. Πατήστε **Clone**. Σε λίγα δευτερόλεπτα ο φάκελος έχει τα ίδια αρχεία με το GitHub.

> Ο φάκελος αυτός είναι πλέον «συνδεδεμένος» με το GitHub. Ό,τι αλλάζετε μέσα του το βλέπει το
> GitHub Desktop και μπορείτε να το ανεβάσετε. **Μη σβήσετε** τον κρυφό φάκελο `.git` που υπάρχει μέσα.
> Αν έχετε κάνει clone και στους δύο υπολογιστές (Windows και Mac), πατάτε πάντα πρώτα **Fetch/Pull**
> (βήμα 4.1), ώστε να έχετε ό,τι ανέβηκε από τον άλλον.

## 4. Ανέβασμα νέας έκδοσης (κάθε φορά που ο Claude σας δίνει νέα έκδοση)

Η διαδικασία είναι ίδια σε Windows και Mac· αλλάζουν μόνο τα κουμπιά του Εξερευνητή/Finder.
Ο Claude σας δίνει ένα zip, π.χ. `diagonismata-1.7.0.zip`, που περιέχει **όλα** τα αρχεία του έργου.

### Βήμα 4.1: Ενημέρωση του τοπικού αντιγράφου
Ανοίξτε το GitHub Desktop. Πάνω αριστερά, στο **Current repository**, να γράφει **MATHEMATICS** και
στο **Current branch** να γράφει **main**. Πατήστε **Fetch origin**. Αν το κουμπί γίνει
**Pull origin**, πατήστε το. Έτσι ο φάκελός σας έχει ό,τι υπάρχει ήδη στο GitHub.

> Αν στα αριστερά, στη λίστα **Changes**, υπάρχουν ήδη αλλαγές που δεν θυμάστε (π.χ. από παλιά
> αντιγραφή), πατήστε δεξί κλικ πάνω τους → **Discard all changes…** πριν συνεχίσετε.

### Βήμα 4.2: Αντιγραφή των νέων αρχείων — Windows

1. Στις **Λήψεις**, δεξί κλικ στο zip → **Εξαγωγή όλων…** → **Εξαγωγή**. Ανοίγει ο φάκελος
   `diagonismata-1.7.0` και μέσα του **ένας ακόμα** φάκελος `diagonismata-1.7.0`. Μπείτε σε αυτόν, ώσπου
   να βλέπετε τα `app`, `build`, `docs`, `README.md`, `CHANGELOG.md` κ.λπ.
2. **Εμφάνιση κρυφών αρχείων:** στον Εξερευνητή → **Προβολή → Εμφάνιση → ☑ Κρυφά στοιχεία**
   (Windows 10: καρτέλα **Προβολή** → ☑ **Κρυφά στοιχεία**). Πρέπει να δείτε και τα **`.github`** και **`.gitignore`**.
3. Πατήστε **Ctrl+A** (όλα) και **Ctrl+C** (αντιγραφή).
4. Στο GitHub Desktop: **Repository → Show in Explorer**. Ανοίγει ο φάκελος `MATHEMATICS`.
5. Πατήστε **Ctrl+V** και στην ερώτηση επιλέξτε **Αντικατάσταση των αρχείων στον προορισμό**.
   Αν ζητηθεί για κάθε αρχείο, τσεκάρετε **Να γίνει αυτό για όλα τα επόμενα**.

### Βήμα 4.2: Αντιγραφή των νέων αρχείων — Mac

1. Στις **Λήψεις**, διπλό κλικ στο zip. Εμφανίζεται ο φάκελος `diagonismata-1.7.0` (αν το Safari τον
   έχει ήδη αποσυμπιέσει μόνο του, χρησιμοποιήστε αυτόν). Ανοίξτε τον: πρέπει να βλέπετε τα `app`,
   `build`, `docs`, `README.md`, `CHANGELOG.md` κ.λπ.
2. **Εμφάνιση κρυφών αρχείων:** μέσα στο παράθυρο του Finder πατήστε **Cmd+Shift+.** (τελεία). Τα
   **`.github`** και **`.gitignore`** εμφανίζονται αχνά. (Με το ίδιο πλήκτρο κρύβονται ξανά.)
3. Πατήστε **Cmd+A** (όλα) και **Cmd+C** (αντιγραφή).
4. Στο GitHub Desktop: **Repository → Show in Finder**. Ανοίγει ο φάκελος `MATHEMATICS`. Κάντε κλικ
   σε κενό σημείο του παραθύρου, ώστε να μην είναι επιλεγμένος κάποιος υποφάκελος.
5. Πατήστε **Cmd+V**. Το Finder ρωτά «Υπάρχει ήδη ένα στοιχείο με το όνομα…»: τσεκάρετε
   **Εφαρμογή σε όλα** και πατήστε **Αντικατάσταση**. Είναι ασφαλές: το zip έχει **όλα** τα αρχεία
   του έργου, και ο κρυφός φάκελος `.git` (η σύνδεση με το GitHub) δεν επηρεάζεται, αφού δεν υπάρχει στο zip.

> Αν ο Claude σας πει ότι σε μια έκδοση **διαγράφηκαν** αρχεία, σβήστε τα και από τον φάκελο
> `MATHEMATICS`. Στις εκδόσεις 1.1.0 έως 1.7.0 δεν διαγράφεται κανένα αρχείο.

### Βήμα 4.3: Έλεγχος, Commit και Push (ίδιο σε Windows και Mac)

1. Γυρίστε στο GitHub Desktop. Αριστερά, στη λίστα **Changes**, φαίνονται τα αρχεία που άλλαξαν,
   με το πλήθος τους στην κορυφή. Ο Claude σας λέει κάθε φορά πόσα περίπου περιμένετε.
   - Αν η λίστα είναι **κενή**, τα αρχεία επικολλήθηκαν σε λάθος φάκελο (ξαναδείτε το βήμα 4.2.4).
   - Αν ο Claude σας είπε ότι άλλαξε το `.github/workflows/build.yml`, **πρέπει** να το βλέπετε στη
     λίστα. Αν λείπει, δεν φαίνονταν τα κρυφά αρχεία (βήμα 4.2.2).
   - Αρχεία `.DS_Store` (Mac) δεν εμφανίζονται, γιατί αγνοούνται αυτόματα.
2. Κάτω αριστερά, στο πεδίο **Summary**, γράψτε π.χ. `Έκδοση 1.7.0`.
3. Πατήστε το μπλε κουμπί **Commit to main**.
4. Πάνω πατήστε **Push origin**. Όταν τελειώσει, το κουμπί γίνεται πάλι **Fetch origin**.

Τελείωσε το δικό σας κομμάτι. Τα υπόλοιπα γίνονται αυτόματα.

## 5. Παρακολούθηση του build

1. Ανοίξτε **https://github.com/EDaskal/MATHEMATICS** και πηγαίνετε στην καρτέλα **Actions**.
2. Πάνω πάνω φαίνεται το build με την περιγραφή του commit σας (π.χ. «Έκδοση 1.7.0»):
   - ● **κίτρινο** κυκλάκι: σε εξέλιξη (6–10 λεπτά),
   - ✓ **πράσινο**: επιτυχία,
   - ✕ **κόκκινο**: αποτυχία (δείτε την ενότητα 8).
3. Όταν γίνει πράσινο, στην αρχική σελίδα του repository, δεξιά, στο **Releases**, εμφανίζεται
   η **«Έκδοση X.Y.Z»** με ένδειξη **Latest**.

Αν πατήσετε πάνω στο build, βλέπετε όλα τα βήματα: Δοκιμές, PyInstaller, **Αυτοέλεγχος του .exe**,
Πρόγραμμα εγκατάστασης, Δημοσίευση έκδοσης. Στο τέλος της σελίδας, στο **Artifacts**, υπάρχει
και εκεί το πρόγραμμα εγκατάστασης.

> Αν ανεβάσετε αλλαγές **χωρίς** νέο αριθμό έκδοσης, το build τρέχει κανονικά αλλά **δεν**
> δημιουργεί νέο Release, οπότε οι εφαρμογές δεν ειδοποιούνται. Το αρχείο υπάρχει μόνο στα Artifacts.

## 6. Η ενημέρωση στον υπολογιστή της εφαρμογής

- **Από την 1.1.0 και μετά:** μόλις ανοίξει η εφαρμογή εμφανίζεται μπλε μπάρα «Υπάρχει νέα
  έκδοση». Πατάτε **Τι νέο & εγκατάσταση → Λήψη και εγκατάσταση**. Η εφαρμογή κατεβάζει τη νέα
  έκδοση, κλείνει, την εγκαθιστά και ξανανοίγει. Ρυθμίσεις, token και λίστες διατηρούνται.
- **Μόνο αυτή τη φορά (από 1.0.0 σε 1.1.0):** η 1.0.0 δεν έχει ακόμα έλεγχο ενημερώσεων. Γίνεται
  με το χέρι:
  1. Στο repository, δεξιά, πατήστε **Releases → Έκδοση 1.1.0**.
  2. Στο **Assets** πατήστε **Diagonismata-Setup-1.1.0.exe** για να κατέβει.
  3. Τρέξτε το. Εγκαθίσταται πάνω στην παλιά (χωρίς απεγκατάσταση), και οι ρυθμίσεις μένουν.

### Επιστροφή σε παλιότερη έκδοση
Στο **Releases** είναι όλες οι εκδόσεις. Κατεβάστε το `Diagonismata-Setup-…exe` της έκδοσης που
θέλετε και τρέξτε το. Εγκαθίσταται πάνω από την τρέχουσα.

## 7. Σημαντικές ρυθμίσεις του repository

- **Το repository πρέπει να μείνει Public**, για να βλέπει η εφαρμογή τις νέες εκδόσεις χωρίς
  κωδικό. Αν γίνει Private, η εφαρμογή δουλεύει κανονικά αλλά δεν ειδοποιεί για ενημερώσεις.
  Οι νέες εκδόσεις εγκαθίστανται τότε με το χέρι από το Releases, και μόνο εσείς έχετε πρόσβαση.
- Η δημοσίευση Release χρειάζεται δικαίωμα εγγραφής για τα Actions. Είναι ενεργό από προεπιλογή.
  Αν το βήμα «Δημοσίευση έκδοσης» αποτύχει με μήνυμα για `permission` ή `403`, πηγαίνετε
  **Settings → Actions → General → Workflow permissions → Read and write permissions → Save**
  και ξανατρέξτε το build (ενότητα 8).

## 8. Όταν κάτι πάει στραβά

| Τι βλέπετε | Τι κάνετε |
| --- | --- |
| Κόκκινο ✕ στο build | Πατήστε πάνω του, μετά στο βήμα με το ✕. Κάντε screenshot τα κόκκινα μηνύματα και στείλτε τα στον Claude. |
| Κόκκινο ✕ στον «Αυτοέλεγχο του .exe» μετά από ενημέρωση | Συνήθως δεν ανέβηκε το κρυφό `.github/workflows/build.yml`. Δείτε το βήμα 4.2.2 (κρυφά αρχεία). |
| «Προσθέστε ενότητα [X.Y.Z] στο CHANGELOG.md» | Λείπει η περιγραφή της έκδοσης. Ζητήστε από τον Claude τη διόρθωση. |
| Το GitHub Desktop δεν δείχνει αλλαγές μετά την αντιγραφή | Τα αρχεία επικολλήθηκαν σε λάθος φάκελο. Χρησιμοποιήστε Repository → Show in Explorer (Mac: Show in Finder) για τον σωστό. |
| «Push rejected» / ζητά Pull | Πατήστε **Pull origin** και μετά ξανά **Push origin**. |
| Build πράσινο αλλά δεν φάνηκε Release | Ο αριθμός έκδοσης είχε ήδη δημοσιευτεί. Ζητήστε από τον Claude νέο αριθμό. |
| Ξανατρέξιμο ενός build | Actions → το build → πάνω δεξιά **Re-run jobs → Re-run all jobs**. |
| Χτίσιμο χωρίς αλλαγή κώδικα | Actions → αριστερά **Build Windows installer** → δεξιά **Run workflow → Run workflow**. |

## 9. Εναλλακτικά: ανέβασμα από τη σελίδα του GitHub (χωρίς GitHub Desktop)

Γίνεται, αλλά θέλει προσοχή:

1. Στο repository: **Add file → Upload files**. Σύρετε **τα περιεχόμενα** του φακέλου της νέας
   έκδοσης, όχι τον ίδιο τον φάκελο και όχι το zip.
2. **Προσοχή:** ο φάκελος **`.github`** συχνά **δεν ανεβαίνει** με σύρσιμο, όπως έγινε την πρώτη
   φορά. Αν ο Claude σας πει ότι άλλαξε το `.github/workflows/build.yml`, ανοίξτε το αρχείο στο
   GitHub → εικονίδιο μολυβιού (Edit) → αντικαταστήστε όλο το περιεχόμενο → **Commit changes**.
3. Αρχεία που διαγράφονται σβήνονται ένα ένα: άνοιγμα αρχείου → **…** → **Delete file**.

Για αυτούς τους λόγους προτείνεται το GitHub Desktop.

## 10. Χάρτης του repository

| Φάκελος / αρχείο | Περιεχόμενο |
| --- | --- |
| `app/` | Ο κώδικας της εφαρμογής (Python) και η οθόνη (`app/ui`, HTML/JavaScript) |

| `.github/workflows/build.yml` | Οι οδηγίες του «εργοστασίου» (GitHub Actions) |
| `build/` | Ρυθμίσεις για το χτίσιμο του .exe (PyInstaller) και του προγράμματος εγκατάστασης (Inno Setup) |

| `README.md` | Γενική περιγραφή του έργου |
